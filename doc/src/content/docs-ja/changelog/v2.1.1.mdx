<Note>

v2.1.1 は npm に公開されていません。公開ワークフローが admission の前に失敗したためです。変更内容は [v2.1.2](./v2.1.2.mdx) に含まれています。

</Note>

このリリースでは、リンターの動作と公開 API は変わりません。npm への公開を OIDC trusted publishing に移行し、リリース手順を単一のテスト済み手順に置き換えました。

## 公開

- `publish.yml` は、固定バージョンの npm 11.21.1 と `--provenance` を使い、npm OIDC trusted publishing で公開するようになりました。npm トークンなどの公開用シークレットは使いません（`1d0f631`）。
- パッケージのビルド・テスト・パックは公開権限のないジョブで行います。別のジョブがダイジェストを確認したうえで、その tarball をそのまま公開します（`1d0f631`）。
- 公開前に、ワークフローは次の 4 点を確認します。タグが正確な形式で `package.json` と一致すること。コミットが `main` 上にあり、そのコミットの CI push 実行が成功していること。そのバージョンが npm にまだないこと（レジストリのエラーで実行は止まります）。dist-tag が後退しないこと（`1d0f631`、`b51ea58`）。
- stable リリースの後は、新しいバージョンより古い `next` タグを削除します。削除に失敗しても報告されるだけで、公開は失敗になりません（`1d0f631`）。
- GitHub Release は changelog から作成し、何度作成し直しても安全です。リリースレポートには各ステップの結果が出ます（`1ae6c82`、`b51ea58`）。

## リリース手順

- リリース手順は `RELEASING.md` の 1 つにまとめました。Claude Code と Codex のスキルはどちらもこれを参照し、テスト済みのリリース CLI は `scripts/release/` にあります（`596a512`、`1ae6c82`）。
- 新しい `release.yml` ワークフローは同じ確認を行い、リリースを開始できます。既定ではドライランです（`1d0f631`）。
- CI は `main` への push 実行をキャンセルしなくなったため、`main` のすべてのコミットに個別の結果が残ります（`b51ea58`）。
