このリリースでは、リンターの動作と公開 API は変わりません。Cloud やエージェントのセッションからリリースを開始する方法を改善しました。

## リリースツール

- 読み取り専用の `candidate` コマンドを追加しました。リリースするコミットを、CI が成功している `main` の先頭（再開時は既存タグのコミット）に固定します。あとで `main` が進んでも、選んだコミットは維持され、その変化が報告されます（`3cc7730`）。
- ホスト型のリリースワークフローは、新規リリース（タグなし）と再開（同じコミットのタグあり）を区別します。別のコミットを指すタグは拒否し、公開済みのバージョンを再開する前には provenance を確認します（`3cc7730`）。
- タグ作成や publish の dispatch が拒否された場合、HTTP ステータス、リクエスト ID、許可されている権限、候補コミットとワークフローのコミット、差分のあるワークフローファイルを報告するようになりました。原因は推測せず、観測結果として報告します（`3cc7730`、`2eb3986`）。
- リリースの run はタイトルにリクエスト ID を持つため、正確な run を追跡できます。権限のプリフライトは gh CLI、GitHub MCP ツール、Actions UI での手動操作の経路を扱います（`3cc7730`、`2eb3986`）。
