This release does not change the linter's behaviour or its public API. It moves npm publishing to OIDC trusted publishing and replaces the release procedure with a single, tested one.

## Publishing

- `publish.yml` now publishes through npm OIDC trusted publishing with a pinned npm 11.21.1 and `--provenance`. No npm token or other publishing secret is used (`1d0f631`).
- The package is built, tested and packed in a job without publishing rights. A separate job publishes that exact tarball after checking its digest (`1d0f631`).
- Before publishing, the workflow checks four things. The tag must be exact and match `package.json`. The commit must be on `main` and have a successful CI push run for that exact commit. The version must be absent from npm (a registry error stops the run). No dist-tag may move backwards (`1d0f631`, `b51ea58`).
- After a stable release, a `next` tag that is older than the new version is removed. A failed cleanup is reported and does not fail the publish (`1d0f631`).
- The GitHub Release is created from the changelog and is safe to create again. The release report lists the outcome of each step (`1ae6c82`, `b51ea58`).

## Release Procedure

- `RELEASING.md` is now the single release procedure. The Claude Code and Codex skills both point to it, and `scripts/release/` holds the tested release CLI (`596a512`, `1ae6c82`).
- A new `release.yml` workflow runs the same checks and can start a release. It does a dry run by default (`1d0f631`).
- CI no longer cancels push runs on `main`, so every `main` commit gets its own result (`b51ea58`).
